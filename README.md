## 二、两大版本深度横向对比 (选型指南)

项目采用“双工程”架构演进，使用者可根据测试设备的 Root 条件与对抗深度选择适合的版本（两版本包名不同，**支持在同一台手机上并存安装**）：

| 评估维度 | 免Root版 (`awei-spoofer-noroot`) | 满血版 (`awei-spoofer`) |
| :--- | :--- | :--- |
| **设备系统门槛** | 零门槛，任意普通 Android 5.0~15 手机均可 | 需解锁 Bootloader + Magisk/KernelSU + LSPosed |
| **生效机制** | Android 原生「开发者选项 - 模拟位置信息应用」 | 系统服务层与进程内动态 Java Hook 拦截 |
| **系统 Mock 标记** | **保留标记** (`Location.isFromMockProvider() = true`) | **彻底抹除**（反射改写位掩码与属性，标记返回 `false`） |
| **多源覆盖度** | 依赖系统分发（部分 SDK 可主动规避） | 覆盖 GPS、Network、Fused、Passive 及 NMEA 报文 |
| **虚拟摄像头** | ❌ 不支持 | ✅ 支持 Camera1、Camera2、CameraX 静态/动态流替换 |
| **传感器步频伪装** | ❌ 不支持（手机静止时步数不增长） | ✅ 自主步频发生器、地磁场合成、活动状态识别接管 |
| **基站与 WiFi 伪装** | ❌ 不支持 | ✅ 抹除周边扫描列表、伪造当前关联 AP / 小区基站 |
| **腾讯系地图等强风控**| ⚠️ 无法生效（强风控 SDK 校验 mock 标记后回落基站）| ✅ 稳定生效（深度抹除特征并接管定位 SDK） |
| **适用场景** | 普通打卡调试、地图路径导航测试、游戏摇杆移动 | 深度自动化测试、防指纹对抗、视频流替换接入研究 |

## 三、免Root版使用与功能全景

### 3.1 启用与前置准备
1. 安装 `AweiSpooferNoRoot`；
2. 进入手机 **系统设置 → 关于手机**，连续点击“版本号”5-7次，直到提示“已进入开发者模式”；
3. 返回设置，搜索或进入 **系统 → 开发者选项**；
4. 找到 **选择模拟位置信息应用**（部分手机显示为“允许模拟位置”），点击并在列表中选中 **阿伟定位伪装·免Root版**；
5. 返回应用状态页，确认体检卡中“模拟位置权限”呈绿色通过状态。

### 3.2 模式与核心操作详解
- **固定点模拟**：在地图上任意点选或长按图钉，直接启动模拟，手机全局位置将锁定在目标经纬度；
- **地点搜索**：支持内置 POI 搜索（Photon / Nominatim 两级自动兜底解析），搜索地点后一键定位并设置；
- **智能路线规划**：
  - 在地图上点选起点与终点，调用内置导航算路接口生成沿真实机动车道/步行道的行进路线；
  - 支持配置模拟速度（支持步行 5km/h、跑步 12km/h、骑行 20km/h 及自定义速度）；
- **一键环线生成**：
  - 选定中心点与目标里程（如 2km、3km、5km），算法自动结合周边真实道路网络生成一段闭合环形路线；
- **实时手绘轨迹与续跑**：
  - 点击“手绘”，在屏幕上手指滑动自由绘制任意复杂的行进折线；
  - 核心体验：在模拟运行过程中，若临时修改手绘路线并保存，系统支持**平滑续跑**，自动将新路线起点修正为当前实时模拟点，杜绝瞬移跳变。

### 3.3 悬浮窗摇杆遥控
- **全局悬浮窗**：启动模拟后，开启悬浮摇杆开关，屏幕将出现半透明虚拟摇杆操作盘；
- **非线性平滑加减速**：采用 Smoothstep 曲线模型，摇杆微推为低速微调，大幅推至边缘为设定最大速度，行走更加自然；
- **多点触控与指针锁机制**：针对手持手机误触屏幕边缘（如手掌压屏）导致的摇杆突变跳跃，底层实现了 Pointer Lock 机制，严格锁定主控制手指，抬手即平稳停驻。

## 四、满血版安装、激活与进阶机制 (Root + LSPosed)

### 4.1 框架与模块激活规范
1. **前置环境**：设备必须通过 Magisk、KernelSU 或 APatch 获得 Root 权限，并成功安装最新版 **LSPosed (Zygisk版)**；
2. **安装应用**：安装 `AweiSpoofer`（满血版）；
3. **⚠️ 极其关键的作用域勾选规则**：
   - 打开 LSPosed 管理器，进入“模块”列表找到 **阿伟定位伪装·满血版**；
   - 勾选启用模块；
   - **在作用域勾选列表中，必须同时勾选：**
     - **[本应用]**（`com.awei.spoofer`）：**必须勾选！** 模块会在主进程 attach 时写入自注入状态回执，用于状态页体检；
     - **[目标测试应用]**（你希望对其进行位置或摄像头替换的目标 App）；
   - 勾选完成后，**强行停止目标应用和本应用，重新打开**即可全量挂载生效。

### 4.2 状态页与自检体检机制
进入满血版主界面的「状态」选项卡，内置了全链路自检诊断卡：
- **Xposed 框架激活**：检测当前系统是否已加载模块类；
- **模块自注入记录**：确认 LSPosed 作用域是否正确勾选了本应用自身；
- **目标心跳检测**：当目标应用启动后，此处会实时显示拦截到的目标应用包名、注入的模块数及最后一次数据拦截时间戳。若出现未拦截现象，可直接在状态页点击“导出运行日志”定位。

### 4.3 全架构虚拟摄像头 (四种输入源详解)
满血版 Hook 劫持了系统 `android.hardware.Camera` (Camera1)、`android.hardware.camera2` (Camera2) 以及 Jetpack `androidx.camera.core` (CameraX) 三层完整相机管线。进入设置页可自由选择以下四种画面源：

```text
       ┌───────────────┐
       │ 1. 本地照片源  │ ──► [自动缩放/居中裁剪] ──┐
       └───────────────┘                          │
       ┌───────────────┐                          │
       │ 2. 视频文件源  │ ──► [ExoPlayer后台循环] ──┼─► [SurfaceTexture/ImageReader] ─► 目标应用相机画面
       └───────────────┘                          │
       ┌───────────────┐                          │
       │ 3. 网络直播流  │ ──► [RTSP/RTMP网络拉流] ──┤
       └───────────────┘                          │
       ┌───────────────┐                          │
       │ 4. 双机副机源  │ ──► [H.264硬件硬解渲染] ─┘
       └───────────────┘
```

1. **本地照片**：选取手机本地任意一张图片，当目标应用开启相机预览或点击拍照时，实时向其管线喂入静态图像帧；
2. **本地视频文件**：选取本地 MP4 视频，后台基于硬件解码循环播放视频帧，支持配置帧率与静音循环；
3. **网络直播流**：支持配置 `rtsp://` 或 `rtmp://` 直播源地址，可将 IPC 监控摄像头画面或远程直播流直接注入到手机相机；
4. **双机远程相机**：副机实时摄像头推流，通过自建中转服务器或局域网直连，把副机当做本机的“外接无线镜头”。

### 4.4 环境与硬件级伪装全景
为了防止安全扫描工具通过交叉硬件比对识别虚拟环境，满血版提供了纵深伪装链：
- **WiFi 扫描结果脱敏**：拦截 `WifiManager.getScanResults()`，清空或伪造 3~8 个假热点 BSSID/SSID，防御基于周边 WiFi 拓扑图的反向地理定位；
- **蜂窝基站脱敏**：拦截 `TelephonyManager.getAllCellInfo()`，防止应用直接读取真实通信基站 LAC/CID；
- **活动识别 (Activity Recognition)**：拦截 Google Play Services 运动状态接口，让设备在定位高速移动时上报 `IN_VEHICLE` 或 `ON_BICYCLE`，杜绝“GPS在以30km/h移动，但活动状态上报STILL静止”的特征冲突。

## 五、自建独立中转服务器部署指南

### 5.1 中继服务器技术原理
双机远程相机在跨公网场景下（如两台手机均使用 4G/5G 蜂窝数据），无法通过局域网 IP 直连。本项目在 `server/` 目录下提供了一套**完全中立、零第三方依赖的高性能 TCP 中继服务器**：
- **信令阶段**：解析紧凑 JSON 控制帧完成副机注册（`reg`）与主机拨号（`dial`）；
- **数据阶段**：拨通瞬间唤醒读管道，切换为绝对透明的 TCP 双向 Binary 管道。配对密码校验与 H.264 视频字节流**对服务器完全不可见且不留存**，保护数据隐私；
- **设备 ID 永久稳定**：副机注册时，服务器会根据持久设备指纹映射出 6 位数字远程 ID，保存在同级 `devices.json` 中，副机即使断线重连，远程 ID 始终保持不变。

### 5.2 极速启动与常驻保活 (systemd)

#### 1. 前台启动测试
服务器只需安装 Python 3.8+，进入 `server/` 目录运行：
```bash
# 默认监听 0.0.0.0:17520
python3 relay_server.py

# 亦可通过环境变量自定义内部监听端口（例如 20000）
AWEL_PORT=20000 python3 relay_server.py
```

#### 2. Linux 生产环境配置常驻后台守护 (systemd)
在 `/etc/systemd/system/awei-relay.service` 中写入：
```ini
[Unit]
Description=Awei RemoteCam Relay Server
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/relay
Environment=AWEL_PORT=17520
ExecStart=/usr/bin/python3 /opt/relay/relay_server.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```
启动服务并配置开机自启：
```bash
systemctl daemon-reload
systemctl enable awei-relay
systemctl start awei-relay
systemctl status awei-relay
```
> **安全组提醒**：请务必在你的云服务器控制台防火墙中，放行对应的 TCP 端口（如 TCP 17520）。

### 5.3 双机远程相机配对操作步骤

1. **副机端配置 (采集端)**：
   - 打开 `AweiRemoteCam` 应用；
   - 勾选“使用中转服务器”；
   - 在中转地址输入框中填入：`你的服务器公网IP:17520`；
   - 点击注册/连接，界面顶部将显示注册成功的 **6位数字远程 ID**（如 `102845`）；
2. **主机端配置 (伪装端)**：
   - 打开 `AweiSpoofer` 满血版设置页，进入“虚拟摄像头设置”；
   - 画面源切换为“双机远程摄像头”；
   - 勾选“经中转服务器连接”，填入相同的 `你的服务器公网IP:17520`；
   - 填入副机显示的 6 位远程 ID；
   - 点击拨号，当目标应用打开相机时，副机画面将实时渲染进主机相机画面中。

## 六、核心底层技术机理深度解析

### 6.1 四源时钟与时间差回拨对抗 (Anti-Detection)
传统虚拟定位仅简单覆写 GPS 坐标，极易被多源校验（Cross-Validation）特征检测器捕获。本项目的处理细节如下：
- **四源时钟差拟真**：系统分发的定位数据中，`fused` 与 `network` 源的时间戳并非实时墙钟时间。本项目在注入时对 Fused 时间戳施加 350~450ms 的自然时钟回拨；
- **Network 源退化策略**：真实基站/网络定位不存在精确的卫星航向与移动速度。模块拦截到网络定位输出时，强制剔除 `speed`、`bearing` 以及卫星数量额外字段，与真实 A-GPS 行为保持一致；
- **差分动态漂移**：在保持基准轨迹不变的前提下，对 network 坐标注入微小的正弦缓变偏移（8~25m），打破“GPS坐标与基站坐标完全逐位相同”的典型作弊特征。

### 6.2 步态惯导与多轴传感器动态合成
针对运动类检测器（检查陀螺仪、计步器是否随位置变化而震动）：
- **自驱动计步发生器**：即使手机完全平放在桌面上，当位置模拟处于行进状态时，`SensorHook` 会根据设定的速度动态计算步频（如步行每秒 1.6~2 步），周期性伪造 `TYPE_STEP_COUNTER` 与 `TYPE_STEP_DETECTOR` 硬件事件；
- **地磁与姿态矩阵合成**：根据行进航向角度（Bearing），动态计算地磁场向量（$X$ 与 $Y$ 分量），模拟设备转向时的自然地磁偏移。

### 6.3 CameraX 异步拍照代理机制
针对基于最新 Jetpack CameraX 架构编写的拍照应用（如 `ImageCapture.takePicture(OutputFileOptions, ...)`）：
- 模块通过反射动态解析 `OutputFileOptions` 中的内部持久化目标；
- 利用动态代理（Dynamic Proxy）劫持回调函数 `OnImageSavedCallback`；
- 在目标文件写入完毕后、通知上层回调之前，以毫秒级时序将伪装 JPEG 字节流强制覆盖写入到目标文件或 MediaStore URI 中，实现 CameraX 拍照链路的完整代理。

## 八、常见问题与排障检索 (FAQ)

#### Q1: 满血版状态页提示“未安装模块 / 模块未自注入”怎么办？
- **排查点**：打开 LSPosed 管理器，确认在模块作用域列表中**是否把本应用自身也勾选上了**。如果只勾选了目标应用而没勾选本应用，主应用无法读取自检测回执。勾选后请强行停止两端应用重试。

#### Q2: 为什么免Root版在某些强风控地图中改完位置后，蓝点依旧跳回真实位置？
- **原理**：免Root版依赖 Android 系统官方模拟通道，系统会在底层强制将每个 Location 标记为 `isFromMockProvider=true`。部分强风控应用如果检测到该标记，会直接丢弃该数据并回退至基站网络定位。此类场景必须使用满血版（Root + LSPosed）在内核层抹除标记。

#### Q3: 虚拟相机在目标应用中出现黑屏或无法替换？
- **排查点**：
  1. 确认目标应用是否已被勾选进 LSPosed 作用域并重启了目标应用；
  2. 确认在设置中已打开“启用虚拟摄像头”总开关；
  3. 部分老旧应用使用 Camera1 API，请在设置中确认是否开启了对应的兼容选项；
  4. 查看运行日志中是否存在 `CameraXPhotoHook` 或 `Camera2Hook` 挂载成功的日志埋点。

#### Q4: 双机远程摄像头画面延迟较高？
- **建议**：
  1. 若两台手机处于同一 WiFi 环境下，建议直接使用局域网直连，无需开启服务器中转；
  2. 使用中转服务器时，建议选择国内低延迟云主机（Ping < 50ms），并确保上行带宽充足。
